S02 — 시나리오와 정답 기준

질문: 가상의 방열판 소재 8개에서 모든 제약조건을 만족하는 상위 2개를 추천하세요. 문서 충돌은 최신 정정으로 해결하고, 누락된 근거를 만들어내지 마세요.

적격 후보만 점수를 계산합니다. recycled_pct는 0–100 값입니다. 최종 점수는 소수 첫째 자리로 반올림하고 동점은 candidate ID 오름차순으로 정렬합니다.

      + 20 * min(recycled_pct / 100, 1)

판정 순서: 확실한 제약조건 위반이 하나라도 있으면 excluded, 위반은 없지만 근거가 빠졌으면 needs_review, 나머지는 eligible입니다. 따라서 후속 조건의 ZETA는 원가 초과로 excluded이지만 부식 근거는 여전히 미확보 상태입니다.

목표: 고정 Action과 에이전트 생성 코드가 같은 계산 환경에서 어떻게 다른지 확인합니다. 기본 경로 이후 선택하는 개발자 확장입니다.[S21] [S22]

시작 조건: L05의 실제 Action 실행을 확인했고, 별도 도구·에이전트 생성 권한과 생성 코드 실행 정책이 준비됐습니다.

실행:

{

      "language": "python",
      "command": "python \"/{{scriptName}}\"",
      "description": "Python standard library only. Analyze original synthetic training data; no network access or new package installation is requested.",

A01 — 비용·quota와 문서 상충 처리

비용은 두 부분으로 나뉩니다: Discovery의 runtime User Messages와 별도 Azure 자원·모델 사용료입니다. GET/list/status/log 조회는 Discovery runtime 과금 대상이 아니지만, 조회하는 동안 상시 인프라 비용은 계속 발생할 수 있습니다. Azure Budget은 보통 알림이며 하드 지출 한도가 아닙니다.[S24]

준비 항목 계획 기준

기타 Workspace/Project Cosmos DB, Storage, Registry·ACR Tasks, 네트워크, 관리 인프라 비용 포함

quota 범위: 구독·모델·버전·배포 유형과 Foundry Quota 화면의 Scope를 함께 확인합니다. 구독 공유 quota로 전환된 모델은 Global Standard에서 같은 모델·버전의 모든 리전이 한 pool을 공유합니다. Scope가 리전명인 모델은 지역별입니다. 리전을 바꾸면 새 quota가 생긴다고 가정하지 않습니다. 기본 경로는 Global Standard이며 Data Zone Standard 등의 지원·quota·데이터 처리 위치는 별도 확인합니다.[S05]

신규 할당량 계산

available_tpm = total_limit_tpm - allocated_tpm
minimum_total_tpm = allocated_tpm + new_allocation_tpm
increase_tpm = max(0, minimum_total_tpm - total_limit_tpm)

allocated_tpm은 기존 배포에 할당한 quota이지 실제 토큰 소비량이 아닙니다. 이미 사용할 모델 배포가 있으면 그 할당을 재사용할 수 있는지 확인하고 신규 필요량에 중복 계산하지 않습니다.

계산 예시 기존 할당 TPM 새로 필요한 TPM 최소 총한도 TPM
Mini 50,000 2,000,000 2,050,000
Embedding 100,000 2,000,000 2,100,000

이는 계산 예시이며 고객의 현재 잔여량이 아닙니다. 총한도를 정확히 2,000,000 TPM로만 요청하면 기존 할당 때문에 부족할 수 있습니다. 여유분과 운영 목표를 포함한 새 총한도를 관리자와 정합니다. 입력란이 추가량을 묻는지 총량을 묻는지도 구분합니다. 예를 들어 총 3,000,000 TPM는 kTPM 단위로 3000입니다.

Azure usage 응답의 설명이 One Thousand Tokens Per Minute 또는 Tokens Per Minute (thousands)이면 값에 1,000을 곱한 뒤 계산합니다. Count 필드만으로 단위를 추정하거나 배포 유형별 quota를 합산하지 않습니다.

부족할 때 확인할 순서

  1. 모델명·버전·Global/Data Zone/지역 Scope와 실제 할당을 다시 확인합니다. gpt-5-mini와 gpt-5.4-mini, TPM과 PTU를 혼동하지 않습니다.
  2. 올바른 디렉터리·구독과 Workspace에 연결된 Foundry 프로젝트를 선택합니다. Discovery Default Project 같은 Foundry 프로젝트와 Discovery Project thermalhol은 다른 리소스입니다. quota 화면을 찾기 위해 새 프로젝트를 만들지 않습니다.
  3. 공식 Foundry 안내의 New Foundry → 해당 프로젝트 → Manage → Quota → Token per minute → Request quota를 사용합니다. 기존 신청이 있으면 먼저 추적하며, 접수·승인·실제 한도 반영을 별도로 확인합니다.
  4. AKSCapacityHeavyUsage 등 지역 용량 오류이면 모델 TPM나 일반 vCPU quota 증액과 구분해 지원 경로로 확인합니다. Cognitive Services quota 조회 오류도 무제한·미사용으로 해석하지 않습니다. 다른 프로젝트의 모델을 임의로 축소·삭제하지 않습니다.
