## 보존과 정리 원칙

- **보존:** 날짜가 있는 실제 응답·실패 기록, 실행 결과, 승인·할당 계산, 실제 API 녹화와 최종 화면. 내용이 같은 빈 배열도 서로 다른 요청의 결과라면 의미가 다릅니다.
- **재생성 출력:** `guide-review/`, `architecture-review/`의 화면·검사 결과는 로컬 문서 빌드가 다시 만듭니다. 클라우드 실행 근거가 아니며 버전 관리하지 않습니다.
- **중간 이미지:** 실제 응답 JSON과 원본 녹화가 남아 있는 단계별 화면, 요약 영상의 중간 프레임, 오래된 렌더링 미리보기는 중복 산출물입니다. 필요한 최종 매체·포스터는 유지합니다.
- **이름만 다른 동일 스냅샷:** 문서·코드가 사용하지 않는 중복본만 제거하고, 시간과 용도가 명확한 원본을 유지합니다.
- **고유 원본:** 고유한 미추적 실행 자료는 불필요 파일로 취급하지 않습니다. 공개용 요약과 구분해 로컬에 보존하며 일괄 커밋하지 않습니다.

로컬 검사 출력은 `npm run check:guides`, `npm run build:architecture`로 재생성합니다. 사용 승인 대기를 설명하는 요약 MP4와 `runs/`의 실제 접근 점검 녹화는 **역사적 기록**이며 현재 Bookshelf·Engine 성공 시연이 아닙니다.

## 공개 범위

저장소와 커밋 이력은 공개 상태입니다. Pages는 이 폴더의 원본 응답·매체를 게시하지 않지만, 그것이 GitHub 저장소의 파일을 비공개로 만드는 것은 아닙니다. 토큰·키·비밀번호·사용자 연락처·브라우저 인증 상태·로컬 절대 경로를 새 증거에 포함하지 않습니다.
